# Controller qualification across reboots

The controller wizard now commits `Saves/CurrentProfile/controller.json` on the UUID-qualified writable card. This is a versioned, bounded JSON record with a SHA-256 integrity checksum, card UUID, actual SDL GUID, measured baseline mapping, and physically checked mapping. A record is restored only for the exact current GUID and full baseline mapping. Missing, corrupt, oversized, unknown-field, duplicate-field, or mismatched records require the physical wizard again; none authorizes a game launch.

The wizard proves D-pad directions and A/B/X/Y (`navigation-8`). Its optional label correction swaps both A/B and X/Y. MENU, volume and shoulder mappings remain the board probe's measured baseline. This record does not claim the user physically verified those additional controls.

Persistence runs on the existing supervisor disk worker. It writes an exclusive temporary file, flushes it, atomically renames it, and flushes the containing directory, using the already qualified FAT `syncfs` fallback where necessary. Card UUID, mount and inode identity are checked through the existing volume pin. No checkpoint pointers or save-state writer locks are changed. A pending controller write survives cancellation of queued reads during shutdown and drains before the final checked volume sync. The UI receives an acknowledgement only after durable saving and protected runtime publication; it withholds game launches until that acknowledgement succeeds.

On successful save or boot restore the worker writes root-owned mode `0600` `/run/console/config/verified-input.json` in the protected runtime directory. This flat version-1 handoff contains the verified GUID, `coverage: "navigation-8"`, hat and 13 named navigation/control bindings; disabled indices are encoded as `65535`. RetroArch may consume these input-only overrides without rewriting its frozen configuration identity. Automatic resume is withheld when controller qualification has not been restored.

The disk worker also snapshots the last 256 KiB of each fixed `/run/console/supervisor.log` and `/run/console/startup.log` into `.tmp_update/logs/`. These are atomic, qualified-card writes. Final shutdown attempts one last snapshot before the authoritative volume barrier; a diagnostic-copy error never fabricates or replaces that barrier.

`console-supervisor/tests/test_controller_persistence.c` is an isolated Linux regression fixture with an active-assertion compilation guard. It exercises checksum/mapping rejection, reboot reopening, mode-0600 runtime publication, a production FAT volume pin, immediate-shutdown pending-write drain, and diagnostics. Run it only in an isolated fixture root, because it intentionally creates the fixed runtime handoff and log paths there. Physical sudden-power-loss endurance remains a separate hardware test.
