# Native menu integration

Normal managed sessions expose upstream Quick Menu, Core Options, Controls and remap management, overlay, latency, rewind and cheat settings. The old custom recovery row menu has been removed. A checkpoint error opens the existing full RGUI with a native A/B-dismissible notice. The implemented MENU+SELECT routing targets that full native menu; parity on the physical handheld remains an acceptance requirement. Resume, Save/Load, state slot, Restart, Close Content and Quit use the authenticated session owner; native content/core replacement and independent save writers are refused with feedback. Physical calibration and global shortcuts remain CloveOS-owned.

Each game/core pair has a writable card profile under `.console/retroarch-profiles/<game-sha256>/<core-sha256>/`. Native configuration, core options and remaps survive exit. The wrapper reapplies ownership-sensitive paths and flags on launch. Reset RetroArch configuration clears these native configuration files; Reset core overrides clears core options and remaps. No checkpoint, battery save or ROM is removed by those resets.

Default-option checkpoints retain the original RASTATE1 container and qualified historical executable identity. When core options differ from the immutable factory profile, a bounded versioned CLOVEOPT suffix carries the core option keys and exact enum values. The whole container is authenticated by the existing checkpoint manifest. Restore validates every option and the complete original container before applying options or deserializing the core. Loading an older checkpoint restores factory options. Option-bearing checkpoints require this or a compatible newer binding and are not backward-compatible with older CloveOS builds. Native display/audio/remap settings are profile settings, not serialized game state.

TGB Dual's dual-cartridge switch remains reserved for the dedicated Trade/Battle launcher because enabling it inside a single-game session changes SRAM topology. Other supported native options use their upstream callbacks; options marked as requiring restart follow upstream core behavior.

English, Spanish and Russian are selected by the frontend before native menu construction. RGUI needs both English and Russian bitmap fonts for Russian. Build-time font installation is described by `provenance/rgui-fonts.json` and `src/console-packaging/install_rgui_fonts.py`; the losslessly decoded raw fonts and CC BY 4.0 notices are installed with the image. The physical portrait-panel projection is corrected for native menu drawing and OSD text, preserving the game's projection. OSD glyph normalization uses logical landscape dimensions so the fixed physical rotation does not distort character aspect.

Qualification records distinguish actual ARM64 programs and real cores under QEMU/SDL substitutions from physical handheld tests. A software matrix recorder verifies GL projection arguments; it is not a physical Mali GPU test.

## Save-error and rewind follow-up

Save errors retain the last committed checkpoint and raw SRAM/RTC. The native notice explicitly says newer progress is unsaved. After A/B dismissal, native Core Options and Controls remain navigable. Resume requests the existing protected continue action only when the owner advertises it. Close Content/Exit uses a native A/B confirmation before requesting the protected unsaved return Home. An implicit native close callback cannot accept that confirmation or resume behind it. Menu-close state is synchronized with the endpoint before an authorized RELEASE.

An authenticated owner may retire its existing core after all writers settle even if an asset or current mutable setting can no longer be re-identified. EXIT starts no save writer and never declares a fresh commit. Capture, load and release still perform identity/policy validation. Pending tasks, wrong ownership and partial-load resume protections remain enforced. A configuration-save failure during an explicitly chosen error exit is logged and cannot trap retirement indefinitely.

Owned normal TGB rewind uses a bounded 16 MiB RAM history and one-frame granularity. Native A/Left/Right enable/disable operations update preference and ownership together. The native granularity/buffer controls cannot create values outside that qualified policy. A persisted enabled preference is normalized during initialization, then the bounded history is reconstructed only after the live factory identity is established. Unavailable history leaves rewind Off. LOAD clears and reseeds history from the authenticated checkpoint's exact SRAM/RTC.

Software qualification includes generated GB/GBC cartridges on real ARM64 RetroArch/TGB, native A/OK disable/re-enable, actual rewind counters, save/exit/cold relaunch/exact paused SRAM/RTC restore/second save, and real disposable-FAT checkpoint I/O failure with native error dismissal, Resume, cancelled exit and confirmed unsaved exit. Endpoint tests separately enforce writer and owner barriers. GL calls and physical inputs/radio are substituted; these tests do not establish physical GPU orientation or handheld shortcut acceptance.

## Stock comparison limits

The supplied Onion 4.3.1-1 archive's nested configs.pak sets RGUI, Miyoo raw MENU=14 and SELECT=2, rewind Off by default, 20 MiB history and granularity 1. Zero 28 raw calibration uses MENU=19 and SELECT=8. The hardware indices differ; semantic parity must be tested on the device. Clove uses upstream 1.19.1, while the stock comparison frontend is 1.15.0. Stock hides Add to Favorites, Cheats and Take Screenshot in Quick Menu; current Clove visibility differs. Undo save/load, direct native content/core replacement and some global lifecycle rows remain owner-restricted; exact stock action/visibility parity is not claimed by the current software tests.
